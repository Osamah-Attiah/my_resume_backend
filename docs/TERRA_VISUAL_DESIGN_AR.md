# تصميم الموقع ولوحة التحكم — مواصفات Terra

التاريخ: 11 سبتمبر 2026. هذا اتجاه تصميم مقترح استجابة لطلب موقع عصري ومميز، مكمل لـ[تحليل التنفيذ](./TERRA_IMPLEMENTATION_SPEC_AR.md). الشاشات لم تُنفّذ بعد؛ المواصفات التالية ليست تقرير اختبار بصري. React و.NET وPDF ATS قرارات ثابتة، والألوان اختيار تصميمي قابل للتعديل.

الهوية المعتمدة: Software Engineer | Flutter & .NET Backend. يُقرأ هذا الملف مع [ملحق الهوية وSEO](./TERRA_SEO_IDENTITY_AR.md)؛ الاسم والمسمى والمحتوى الأساسي يجب أن تبقى نصوص HTML واضحة قابلة للفهرسة، مع مراعاة الأداء عند تنفيذ الصور والحركة.

## 1. اتجاه التصميم

الزائر مسؤول توظيف أو مطور يريد فهم التخصص ورؤية دليل عملي عليه. أول شاشة تعرض الاسم والمسمى، ثم طريقًا واضحًا إلى المشاريع والسيرة. يعتمد التميز على الطباعة وتوزيع المساحات وصور الأعمال الحقيقية.

| الاتجاه | التكوين والشخصية | الحركة | الميزة والمقابل |
|---|---|---|---|
| معرض أعمال تحريري — المختار | خلفية عاجية، عناوين فحمية، أخضر داكن، مشروع بارز وصفوف أعمال | استجابة قصيرة وهادئة | يجمع الشخصية ووضوح القراءة؛ يحتاج صور مشاريع جيدة |
| استوديو تقني داكن | فحمي ونص فاتح وصور تطبيقات كبيرة | انتقالات خفيفة | يبرز صور التطبيقات؛ يحتاج عناية أكبر بالتباين وكثافة النص |
| دفتر هندسي | أبيض وشبكة دقيقة وأرقام أقسام وتفاصيل تقنية جانبية | تغيّر حالة مباشر | مناسب لشرح القرارات التقنية؛ أقل دفئًا وأكثر تخصصًا |

نختار معرض الأعمال التحريري. نستفيد من مبادئ الفهارس المطبوعة ومعارض المنتجات: عنوان واضح، صورة لها مساحة كافية، وتفاصيل تتدرج عند فتح المشروع. لا تنسخ هوية موقع معروف أو تخطيطه.

لا تضف جسيمات أو خلفيات فيديو أو 3D أو مؤشر ماوس خاص أو terminal تمثيلي. لا عدّادات سنوات أو عملاء أو شعارات شركات لم يزوّدنا بها المالك. إذا كان لديه مشروع واحد، يعرض الموقع مشروعًا واحدًا بتفاصيل جيدة.

## 2. رحلة الزائر والمالك

```text
رابط تقديم موجّه → بروفايل محدد → مشروع ودليل العمل → تنزيل PDF أو التواصل
رابط LinkedIn العام → البروفايل الافتراضي → الأعمال → تفاصيل مشروع
دخول المالك → اختيار بروفايل → تعديل ومعاينة → حفظ → مراجعة النشر → نتيجة
```

زر الموقع الأساسي في أول شاشة: «استعرض أعمالي»، وينقل إلى قسم المشاريع. زر ثانوي ظاهر: «تحميل السيرة»، وينزل PDF بلغة الصفحة. تبديل اللغة يحافظ على نفس البروفايل والمشروع المقابل عند توفر الترجمة المنشورة. لا تجعل الزائر يختار من عدة بروفايلات قبل رؤية المحتوى.

في تفاصيل المشروع، «تجربة المشروع» هي العملية الرئيسية عندما يوجد رابط حقيقي، و«عرض الكود» ثانية. عند غياب التجربة يتقدم رابط الكود. لا زر معطل دائمًا يوحي بوجود ميزة غير متوفرة.

## 3. تكوين الصفحة العامة

حاوية قصوى 1200px. شريط علوي: اسم المالك، روابط الأعمال/نبذة/التواصل، وتبديل اللغة. لوحة التحكم لها عنوان مستقل، ولا يلزم رابط لها في التنقل العام.

على desktop: شبكة 12 عمودًا؛ الهوية تأخذ 7 أعمدة عند inline-start، ومشروع بارز 5 عند inline-end. في العربية تبدأ الهوية يمينًا، وفي الإنجليزية يسارًا.

ترتيب الهوية:

1. الاسم الحقيقي كما أدخله المالك، بحجم كبير واضح.
2. المسمى `Software Engineer | Flutter & .NET Backend` كنص، مع التفاف طبيعي عند الحاجة. يمكن إبراز Software Engineer بسطر وFlutter & .NET Backend بسطر ثانٍ دون تغيير المعنى. بالعربية: «مهندس برمجيات» ثم «تطبيقات Flutter وخدمات خلفية باستخدام .NET».
3. ملخص البروفايل؛ يستهدف المحرر 3–4 أسطر موجزة، دون قص النص آليًا إن زاد.
4. زر الأعمال وزر تنزيل السيرة.
5. روابط GitHub وLinkedIn إذا كانت موجودة.

المنطقة المقابلة تعرض صورة أول مشروع في ترتيب الويب، مع اسمه ونوعه الشخصي وتقنياته. لا تحتاج حقل featured جديدًا؛ ترتيب المالك يحدد المشروع البارز. الهدف وضع دليل ملموس بجانب الهوية.

عند غياب الصورة يعرض وصف مشروع منظم بدون screenshot مختلقة. وعند غياب المشاريع تصبح المقدمة أحادية العمود وتختفي الدعوة للأعمال. صورة المالك اختيارية وصغيرة؛ لا تُفرض مساحة portrait ضخمة.

مخطط ترتيب معلومات، وليس mockup نهائيًا:

```text
┌─────────────────────────────────────────────────────────┐
│ الاسم          الأعمال · نبذة · تواصل        العربية/EN │
├─────────────────────────────────────────────────────────┤
│ هوية: اسم + مسمى + ملخص    │ صورة أول مشروع مختار         │
│ أعمالي / تحميل السيرة      │ اسمه · نوعه · تقنياته        │
├─────────────────────────────────────────────────────────┤
│ 01 أعمال مختارة: صورة كبيرة + وصف + تجربة + GitHub       │
│    مشروع تالٍ: صف بصورة أصغر ومحتوى واضح                 │
├─────────────────────────────────────────────────────────┤
│ 02 مهارات تقنية: مجموعات نصية حسب التصنيف                │
│ 03 نبذة وتعليم: نص موجز وسجلات بتواريخ واضحة             │
│ 04 تواصل: بريد · LinkedIn · تحميل السيرة                 │
└─────────────────────────────────────────────────────────┘
```

أرقام الأقسام علامات ترتيب فقط؛ ليست أرقام إنجازات. تُحجب عن قارئ الشاشة إذا كانت زائدة. يحترم الموقع ترتيب الأقسام الذي ضبطه المالك بدل فرض تسلسل الرسم دائمًا.

## 4. المشاريع وصفحة التفاصيل

المشروع الأول يأخذ مساحة أوسع: صورة بنسبة مقترحة 16:10 ونص بجانبها. المشاريع التالية صفوف تفصلها خطوط خفيفة، وليست بطاقات متساوية تزيل أهمية المشروع الأساسي.

- صور التطبيقات تستعمل contain عند الحاجة حتى لا تُقص الواجهة، مع خلفية neutral حولها.
- أبعاد محجوزة وalt باللغة الصحيحة؛ لا قفز في التخطيط عند اكتمال الصورة.
- النوع شارة نصية «مشروع شخصي» أو النوع الحقيقي، لا شارة توحي بوجود عميل.
- التقنيات نص أو tags هادئة؛ لا تملأ المقدمة بعشرات الشارات.
- رابط التفاصيل منفصل عن روابط التجربة والكود؛ لا anchor داخل anchor.
- إطار هاتف بسيط جائز لصورة تطبيق فعلية، دون اختلاق منتج أو شاشة.

صفحة التفاصيل: عودة للبروفايل، اسم، ملخص ودور، صورة رئيسية، وصف، نقاط العمل، تقنيات، معرض صور وروابط. استخدم حقول project الحالية؛ لا تضع تحديات أو نتائج مختلقة. المالك يكتبها في description/highlights إن أراد.

تكبير الصورة يمكن أن يفتح dialog يدعم Escape وحجز focus وإعادته بعد الإغلاق. العودة إلى القائمة تحفظ التمرير الطبيعي للمتصفح. لا حاجة إلى route transitions معقدة.

## 5. نظام الألوان والخطوط

| token | القيمة | الاستخدام |
|---|---|---|
| `--canvas` | `#F6F5F0` | خلفية عاجية |
| `--surface` | `#FFFFFF` | النماذج والطبقات |
| `--surface-subtle` | `#ECEEE7` | منطقة مشروع أو اختيار |
| `--ink` | `#17221D` | النص والعناوين |
| `--ink-muted` | `#526057` | وصف ثانوي وتواريخ |
| `--accent` | `#245C42` | أزرار وروابط أساسية |
| `--accent-hover` | `#194730` | hover/pressed |
| `--on-accent` | `#FFFFFF` | نص الزر الأساسي |
| `--border-subtle` | `#D5DBD2` | فواصل زخرفية فقط |
| `--control-border` | `#758277` | حدود حقول مرئية |
| `--danger` | `#A42B28` | خطأ مع نص/رمز |
| `--warning` | `#7B4E10` | تحذير على سطح فاتح |
| `--focus` | `#245C42` | حلقة focus، 2px مع offset |

تعرف primitives ثم semantic tokens في stylesheet مشتركة. المكونات تستهلك دلالات الألوان بدل تكرار hex. اللون لا يكون المؤشر الوحيد للحالة.

- خطوط مقترحة: Noto Sans Arabic للعربية وManrope للاتينية؛ self-hosted WOFF2 مع ملفات الترخيص. لا جلب خطوط وقت العرض من خدمة خارجية.
- الاسم: `clamp(2.5rem, 5vw, 4.5rem)`؛ المسمى 20–28px، عناوين الأقسام 28–36px، المتن 16–18px، والثانوي 14px على الأقل.
- line-height عربي للمتن 1.7–1.85، وإنجليزي 1.55–1.7؛ العناوين نحو 1.3.
- لا letter-spacing للعربية، واعزل URL والبريد والتقنيات المختلطة اتجاهيًا.
- وحدات المسافة 4/8/12/16/24/32/48/64/96px؛ بين الأقسام 80–112px desktop و48–64px mobile.
- حواف 8px للتحكم، 12px للصور، 16px للdialogs. ظلال للطبقات العائمة فقط عادة؛ الفواصل تكفي لمعظم الصفحة.
- light theme متقن للإصدار الأول. dark mode اختياري لاحق، دون زر شكلي لا يعمل.

## 6. لوحة التحكم

نفس الهوية اللونية، مع مساحة تحرير بيضاء وكثافة أعلى. sidebar بعرض 232px عند بداية اتجاه اللغة، topbar 64px، والباقي للعمل. لا hero كبير داخل الإدارة.

الرئيسية تبدأ بما يحتاج إجراءً: ترجمات ناقصة، تعديلات غير منشورة، أو نشر فاشل، ثم قائمة بروفايلات وسجل نشر. لا charts لزوار لم يُنفذ تتبعهم.

محرر البروفايل:

- toolbar: اسم البروفايل، حالة الحفظ، زر حفظ، وزر مراجعة النشر.
- selector لغة المحتوى منفصل عن لغة التطبيق.
- قائمة أقسام مع اختيار ظهور web وPDF وترتيبهما.
- على شاشة واسعة: تحرير 55% ومعاينة 45% مع divider.
- المعاينة تبدّل «الموقع» و«السيرة». السيرة ورقة بيضاء بحدود صفحات وخيار تكبير، دون توريث ثيم الإدارة.
- نتائج التحقق تحدد الحقل وتعيد focus إليه عند النقر.
- توليد PDF يظهر الحالة، ثم الملف ولغته وتاريخ توليده. لا تعرض ملفًا قديمًا على أنه أحدث توليد.

مراجعة النشر تعرض الموقع المستهدف، البروفايلات واللغات، وبيانات التواصل التي ستصبح عامة والتحذيرات. زر «نشر هذه النسخة» ينتقل لحالة العملية؛ تبقى النسخة المنشورة الحالية ظاهرة بجانب العملية الجارية.

## 8. الجوال وRTL وإتاحة الوصول

- أقل من 640px: هامش 20px، النص ثم الصورة، أزرار تلتف أو تتمدد وصفوف المشاريع تصبح عمودًا.
- 640–1023px: هامش 32px وتوزيع متوسط؛ لا معاينة ضيقة بجانب نموذج ضيق.
- 1024px فأعلى: حاوية الموقع 1200px وsidebar الإدارة ثابتة. تقسيم التحرير/المعاينة يبدأ عند 1280px إذا سمحت المساحة الفعلية.
- على الجوال: drawer للتنقل الإداري وtabs «تحرير / معاينة». أزرار sticky عند الحاجة، مع مساحة تمنع تغطية الحقول واحترام safe-area.
- لا تمرير أفقي للصفحة عند 360px. الجداول الإدارية تصبح قوائم؛ ورقة PDF وحدها يمكنها scroll داخل منطقتها مع تحكم في التكبير.
- logical CSS مثل padding-inline وinset-inline-start. أسهم التنقل تتبع الاتجاه، والشعارات والبريد والروابط لا تنعكس.
- أهداف لمس 44×44px، skip link، focus واضح، headings مرتبة، labels للأزرار والحقول، وإرجاع focus بعد dialog.
- تباين مستهدف 4.5:1 للنص العادي و3:1 للنص الكبير والتحكم. افحص الحالات الفعلية، وليس الألوان منفردة.
- اختبر zoom 200%، اسمًا طويلًا، ملخصًا عربيًا طويلًا، وأرقامًا وتقنيات لاتينية مع نص عربي.

## 9. الحركة والأداء وPDF

استجابة hover/focus بين 140–180ms، وظهور أقسام اختياري 220–300ms بإزاحة ≤8px. المحتوى ظاهر في HTML حتى دون JavaScript. reduced-motion يزيل الحركة غير الضرورية. لا parallax أو auto-carousel أو smooth-scroll إجباري. CSS تكفي ما لم توجد حاجة محددة لمكتبة حركة.

الصور محسنة بأبعاد ثابتة، وتُحمّل الخطوط اللازمة للغة فقط؛ لا تحميل كل صور المشاريع عند دخول الصفحة. أهداف الأداء والـSEO في التحليل الأساسي تبقى سارية.

تصميم الموقع مستقل عن ATS PDF. ملف السيرة أبيض وأسود، عمود واحد، بلا صور أو بطاقات أو sidebar. تحميل PDF لا يصوّر صفحة الموقع. الموقع والـPDF يشتركان في المحتوى المختار، ولكل منهما قالب خاص.

## 10. تسليم Terra والمراجعة

1. ابدأ بـtokens ومقدمة وصف مشروع، ثم محرر بروفايل ومعاينة PDF ببيانات اختبار معلّمة؛ لا تنتج جميع الشاشات بقالب بطاقات موحد.
2. أرفق screenshots فعلية للعربية والإنجليزية عند 390px و1440px، وافحص 360/768/1024px وظيفيًا.
3. افحص keyboard وreading order والتباين وحالات الخطأ والفراغ وغياب الصورة ولغة PDF غير المتاحة.
4. حافظ على عقود البيانات. أي حقل جديد يحتاج سببًا وmigration وواجهة تحرير، لا hardcode.
5. أرفق تقريرًا يميز الاختبارات الآلية والمراجعة البصرية والقيود المتبقية. هذه الوثيقة لا تثبت تنفيذ أي شاشة.
